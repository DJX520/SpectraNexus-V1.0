# BlackDeck V2.2 + LabOS V5.2 紫金版 · 直接部署步骤

> 配套：M5Stack Cardputer-Adv K132-Adv + Cap CC1101 U219、RDK X5 Ubuntu 22.04、Windows Arduino IDE 2.3.5 / ESP32 Core 3.3.7。
> 测试状态：RDK 软件自动化测试和模拟串口通信通过；真实 ADV ↔ RDK USB 联调和新固件完整 Arduino 编译仍需在现场完成。

## A. Windows 烧录 Cardputer-Adv

1. 解压完整 ZIP，打开 `firmware/BlackDeck/BlackDeck.ino`（不要只打开 .cpp）。
2. 在 Arduino IDE 的开发板管理器核对 `esp32 by Espressif Systems` 3.3.7；库管理器核对 `M5Cardputer`、`M5Unified`、`M5UnitUnifiedNFC` 及其依赖、`RadioLib 8.x`、`NimBLE-Arduino 2.x`。按库管理器的依赖安装提示操作。
3. 选择 `ESP32S3 Dev Module`、Flash Size `8MB (64Mb)`、PSRAM `Disabled`、USB CDC On Boot `Enabled`、Partition Scheme `Custom`，以及实际 COM 端口。
4. 确认 `firmware/BlackDeck/partitions.csv` 与 `BlackDeck.ino` 位于同一文件夹。Flash APP 上限为 `0x7E0000 = 8,257,536 字节`，而非 IDE 初始显示的 16,777,216 字节。
5. **可选但建议：** 将 `firmware/boards.local.txt` 合并到 Arduino Core 的 `boards.local.txt`（与 `boards.txt` 同级），重启 IDE；仍选 `Custom`，编译时 Maximum 应为 `8257536 bytes`。已存在同名文件时先备份并合并，不要覆盖其他项目配置。
6. 先点击“验证”；确认实际程序大小低于 8,257,536 字节。再用 Cardputer-Adv 下载模式上传（设备关机、按住 G0，插入 USB 数据线，再松开）。首次更换分区前请备份设备原有数据。
7. 上电应显示 BlackDeck 主界面；按 `V` 打开 Showroom。USB 连接 RDK 前**关闭 Arduino 串口监视器**。

## B. 安装扩展帽及供电

1. Cardputer-Adv 完全断电，再插入 Cap CC1101 14 针扩展端口，确认方向与接触可靠。不要热插拔。
2. 433 MHz 测量装配 433 MHz 天线；315 MHz 测量装配 315 MHz 天线；868/915 MHz 使用匹配的 868/915 MHz 天线。更换天线前关闭射频采集。
3. ADV 通过 USB-A 转 USB-C 的**数据线**接 RDK X5 的 USB Host；RDK X5 使用其正常的独立供电。

## C. RDK X5 安装、启动和开机自检

```bash
# 从 ZIP 内将 rdk 文件夹复制到 RDK X5 的 ~/BlackDeck_LabOS_V5_2/rdk
cd ~/BlackDeck_LabOS_V5_2/rdk
sudo apt update
sudo apt install -y python3 python3-venv python3-pip
bash install_rdk.sh
.venv/bin/python -m unittest discover -s tests -v

# 确保访问 USB 串口的账号已加入 dialout 组，执行后注销并重新登录
sudo usermod -aG dialout "$USER"

# 只检查 LAB5 握手与设备信息（不扫描）
.venv/bin/python -m labos.check_device --port auto

# 启动 Web 服务器
bash run_rdk.sh
```

RDK 本机：`http://127.0.0.1:8080`。

Windows 访问：打开 Windows 终端，保持以下命令窗口运行：

```text
ssh -L 8080:127.0.0.1:8080 用户名@RDK_IP
```

将 `用户名` 和 `RDK_IP` 换成你的实际账号与 IP，Windows 浏览器打开 `http://127.0.0.1:8080`。

**注意：** 服务仅监听 RDK 的 127.0.0.1，不能直接访问 `http://RDK_IP:8080`；默认不开放到公网。

## D. 首次联机验收（建议按顺序）

1. 进入网页 `06 部署与诊断`，点击 **USB 一键通信自检**：应得到 `ok: true`、`protocol: LAB5`、`firmware`、`board` 和两项毫秒响应时间。
2. 进入 `01 总览与采集`，点击 **读取设备状态**，核对 `flash_bytes: 8388608`、`board: Cardputer-Adv`。若值不同先核对目标硬件。
3. 点击 WiFi 和 BLE：实际出现周边观测记录，来源应为 `ADV_USB`，未发现设备时允许 `0` 条。
4. 选择安装好的匹配天线，再点 433 MHz / 315 / 868 / 915 的一次 RF 接收采样：记录应包含 `frequency_hz` 和 `rssi`。四频段要分别测试。
5. 把自己的 NFC-A 测试标签靠近扩展帽，再点 NFC：能够识别时应出现 `uid`，未检测到时可能是 `0` 条和 `reason: no_tag`。
6. 转到 `03 实验管理` 新建会话，再采集、导出 CSV/JSON，点击 **打印报告** 通过浏览器保存 PDF。
7. `05 全屏演示驾驶舱` 默认是数据库回放，不是实时 RF；按 **视觉模拟演示** 可安全演示动效，模拟数据不会写入数据库。

## E. 常见情况

| 现象 | 处理 |
| --- | --- |
| 自检提示无串口 | 更换数据线；查看 `/dev/ttyACM*`、`/dev/serial/by-id/*`；确认 ADV 的 USB CDC On Boot 已启用 |
| 提示 Permission denied | 执行 `sudo usermod -aG dialout "$USER"`，注销后重新登录 |
| USB 被占用 | 关闭 Arduino Serial Monitor、minicom、screen 等串口软件 |
| 自检协议不匹配 | ADV 和 RDK 都使用本包 V2.2 / V5.2；确认串口确实连到 ADV 而非其他串口模块 |
| RF 没数据、RSSI 异常 | 检查扩展帽及对应天线；保证频段设置和天线匹配；重复单次测量 |
| NFC 未读到卡 | 确认标签为兼容 NFC-A 并靠近天线；重新执行一次采集；本版只读且未覆盖全部卡类 |
| 设备显示在线但扫描失败 | 自检仅确认 USB 协议，不代表各传感器均通过实测；核对具体模块日志 |
| 网页没有历史曲线 | 先创建会话并采集，或者切换到明示的模拟演示模式 |
| Arduino 仍显示 16MB Maximum | 不得把它当作真实容量；核对分区并确保编译结果小于 8,257,536 B |
| 离线 AI 运行卡顿/异常 | Flash 通过仅代表能容纳程序，无法保证内存/模型运行通过；记录 Heap 与报错再定位 |

## F. 可选功能

- RDK 上安装 Whisper.cpp 和所需模型后，可在配置文件中设置 `WHISPER_CLI`、`WHISPER_MODEL`，再使用 `04 AI 分析助手 > 转写 WAV`。
- 如已有 Ollama 和可运行的小模型，可在 `rdk/config.env` 填写 `LABOS_AI_BACKEND=ollama` 和 `OLLAMA_MODEL=具体模型名称`。未安装不会影响本地实验和规则助手。
- 服务常驻可在安装验证后运行 `bash scripts/install_user_service.sh`。此步骤非首次部署必需。
